# FX — Visual Foundation Decision & Audit

## الهدف والحدود
اعتماد **واجهة أساس واحدة** لـ FX AI Creative Lab، وانتقاء أقوى القرارات من المراجع بدل دمج سبعة مشاريع أو نسخ واجهات كاملة. هذه المرحلة بصرية وتجربة استخدام فقط. ملف المشروع الأصلي محفوظ كما هو داخل `original-project-untouched.zip`؛ لم يتم تعديل Backend أو مفاتيح البيئة أو منطق مزوّدي الذكاء الاصطناعي.

## قرار الاتجاه البصري
**الاختيار: Cinematic Editorial Workspace** — هوية سينمائية داكنة ومميزة، مع بنية عمل عملية وواضحة.

- **Visual DNA من Stitch:** خلفية كربونية، تباين ذهبي/برونزي محدود، مظهر استوديو إنتاج حقيقي، بيانات المشهد والـ storyboard، وإحساس إخراجي لا يشبه لوحة SaaS عامة.
- **UX من Figma Make:** هرمية تحريرية قوية، مساحة تنفّس، فصل واضح بين الموجز والرؤية والفكرة والسيناريو، وإمكانية مراجعة المخرجات قبل الانتقال.
- **سلوك مساحة العمل من v0:** شريط مراحل ثابت، تنقّل سريع، مساحة رئيسية مركزة، لوحة مساعدة اختيارية، اختصارات وأدوات تشغيل مفهومة.
- **مبدأ تدفق المنتج من Lovable:** حالة مشروع واحدة متماسكة، أفعال أساسية ظاهرة، واستمرارية العمل بين المراحل بدل صفحات منفصلة لا تتشارك السياق.
- **أفكار من Atelier / Cinematic Simulation:** المشاهد، الـ shot list، معلومات الكاميرا والصوت والإضاءة، وتلميحات timeline؛ تُستخدم عند مرحلة السيناريو فقط ولا تسيطر على كامل التطبيق.

## ما سنأخذه — وما لن نأخذه

| المجال | القرار |
|---|---|
| الهوية | كربوني `#0A0C10`، عاجي للنص، كهرماني/برونزي `#D4AF37`، صدأ محدود للتنبيه |
| الخطوط | خط عربي واضح (IBM Plex Sans Arabic أو Noto Sans Arabic) مع خط عرض تحريري وعناصر mono للبيانات التقنية |
| التنقل | أربع مراحل رئيسية: Brief → Insight → Concept → Script؛ مع شريط تقدم ثابت |
| الهيكل | مساحة عمل ذات عمود جانبي خفيف + محتوى رئيسي + لوحة سياقية اختيارية؛ تتحول إلى واجهة مدمجة على الهاتف |
| البطاقات | حواف دقيقة وحدود هادئة؛ لا تحويل كل شيء إلى كروت مدوّرة ضخمة |
| التفاعل | حالة واضحة للمرحلة، تحرير المخرجات، إعادة التوليد، نسخ/تصدير، ورسائل تحميل/خطأ قابلة للفهم |
| العربية | RTL أصلي وليس مجرد محاذاة يمين؛ دعم EN/LTR مع تبديل الاتجاه فعليًا |
| تجنب | تكديس كل أدوات الرندر في الصفحة الرئيسية، مؤشرات إحصائية مزخرفة بلا وظيفة، ودمج واجهات المراجع كما هي |

## اختيار كل مرجع
- **Stitch / FX AI Creative Lab:** المصدر الأساسي للهوية واللغة السينمائية.
- **Stitch / VFX Prompt Lab + Storyboard Dispatch:** تُستعار تفاصيل المشاهد والمخرجات السينمائية، ولا تُستخدم كهيكل الصفحة الرئيسية.
- **Stitch / Radical Thinking State:** تُستعار طريقة عرض محركات التفكير ومخرجاتها المنظمة، مع تقليل كثافة اللوحة.
- **Stitch / Strategic Audit & Governance:** تُستعار فكرة حالة العملية والوضوح، لا واجهة التدقيق الثقيلة.
- **Stitch / Neural Render Queue:** تُستعار مؤشرات حالة التوليد عند الحاجة فقط؛ لا نُدخل Render Farm في أساس المنتج.
- **Stitch / Export Production Dispatch:** تُستعار فكرة التصدير والتسليم المنظم في مرحلة المخرجات.
- **Figma Make:** هرمية المحتوى والتدرج التحريري ومراجعة المخرجات.
- **v0:** تقسيم المراحل والتفاعل المباشر ومساحة العمل القابلة للتوسع.
- **Lovable:** تدفق المنتج والربط بين الحالات، بعد التأكد من مكوناته الفعلية؛ لا نفترض أن أي تكامل API جاهز لمجرد وجود الواجهة.
- **Atelier + Cinematic Simulation:** عناصر إخراج متقدمة اختيارية لمرحلة السيناريو، وليست عبئًا دائمًا على كل مرحلة.

## ملاحظات فنية مهمة
1. ملفات المراجع تضم تطبيقات متعددة وتقنيات مختلفة (React/Vite وNext وغيرها). لا يصح نسخ مكوناتها مباشرة داخل المشروع الأساسي من غير مواءمة؛ سننقل القرارات التصميمية والسلوكيات المطلوبة إلى React/Vite الموجود بالفعل.
2. المشروع الأساسي يحتوي على Frontend وBackend ومزوّدي AI. في هذه المرحلة لا نغيّر عقود API ولا ملفات `.env` ولا أي كود في `backend/`.
3. ملفا الـ prompt داخل الأرشيف الأساسي متطابقان بايتًا ببايت (الحجم 7,479 بايت لكل منهما). هما نسخة مكررة من prompt تدقيق Backend؛ لا يمثلان مرجعين تصميميين مختلفين. لم نحذف أيًّا منهما.
4. `text.html` داخل المشروع الأساسي صفحة تعريف/تسويق، وليست واجهة مساحة العمل. أما ملفات Stitch فبعضها مراجع تصميمية وبعضها نماذج مستقلة وليست نسخة جاهزة للإنتاج.
5. المعاينة المرفقة **prototype بصري مستقل** لتثبيت الاتجاه، وليست موصولة بالـ Backend أو ادعاءً بأن أزرار توليد الذكاء الاصطناعي تعمل فعليًا.

## بوابة المرحلة التالية
بعد مراجعة اتجاه الواجهة واعتماده، تكون الخطوة التالية نقل هذا النظام البصري إلى `app/src/App.tsx` و`app/src/styles.css` مع الحفاظ على وظائف الـ API الحالية، ثم فحص TypeScript وVite build. يظل Backend خارج نطاق التعديل حتى اكتمال الواجهة وموافقة المستخدم.
