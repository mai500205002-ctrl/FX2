## Priority and category rules

- **P0** — blocks reliable baseline or presents a high-impact acceptance/security/data-integrity uncertainty that must be resolved before relevant release gates.
- **P1** — required for backend correctness, security, provenance, persistence, or end-to-end reliability before final acceptance.
- **P2** — meaningful but not a current single-user acceptance blocker; schedule only after P0/P1 and scope approval.
- Priority is a planning judgment, not a measured incident probability.

Risk categories follow the controlling roadmap: **Correctness, Security, Provenance, Persistence, End-to-end reliability**. **Compatibility, Cost, and Data** are additional tags drawn from the roadmap's increment-report template. A listed gap is an evidence/acceptance gap unless explicitly marked as a source-confirmed implementation boundary; it is not automatically a confirmed defect.

## Ordered implementation proposal

Follow the controlling roadmap's BE-03 through BE-18 order and gates. The first proposed work is the smallest independent implementation slice; all items below are proposals, not work performed in BE-02.

1. **BE-03A — Fail-fast validation for `AI_MAX_OUTPUT_TOKENS`.** Evidence: `src/gateway/llm-gateway.ts::callLLM` validates this setting only when a model request is made; startup logging in `src/index.ts::logStartupConfig` reports providers but does not validate it. This one-setting startup check is bounded and prevents a misconfigured server from appearing healthy until first generation. Test invalid, valid minimum, and maximum 512; acceptance: invalid values fail startup with a safe actionable error; valid boundary values start and pass build/tests. Depends on: recorded BE-00 baseline; no provider call required.
2. **Complete BE-03 runtime/config integrity.** Validate remaining required/optional config, safe diagnostics, readiness and shutdown only after the focused first slice. Do not mix provider live calls into configuration tests.
3. **BE-04A — Freeze route contracts.** Test each API inventory row for request validation, auth/exemption, response/error shape, side effects and compatibility (G-01). Independent functional scope; follows the roadmap gate after BE-03.
4. **BE-05/06 — Authentication and authorization.** Complete route-by-route auth/session/token/proxy review, then privileged-operation tests (G-02). Treat roadmap concerns as audit leads until reproduced.
5. **BE-07 — CreativeIR and domain contracts.** Verify schema, serialization, versioning, identity and evidence-state boundaries.
6. **BE-08 — Discovery and candidate generation.** Verify lens attribution, partial failures, candidate contract/provenance and bounded spend.
7. **BE-09/10 — Court, reviewer and bounded revision.** Verify rubric decisions, fallback states, objections and revision limits.
8. **BE-11 — Memory, metabolism and entropy.** Resolve G-06; test persistence failures and keep lessons distinct from facts/outcomes.
9. **BE-12/13 — Browser and claim/evidence linkage.** Resolve G-07 in controlled runtime conditions; do not broaden Browser capabilities.
10. **BE-14/15 — Gateway/provider routing then budget enforcement.** Resolve G-04/G-05; preserve no-paid-call rule and process-local limits.
11. **BE-16/17 — Run recovery, persistence, approval and end-to-end provenance.** Resolve G-03/G-05/G-06 with fault injection, restart and artifact-binding checks.
12. **BE-18 — Consolidated verification and acceptance readiness.** Execute relevant checks on a clean recorded tree and reconcile all reports.
13. **Scope decisions, not automatic implementation:** G-08 (live trends), G-09 (SaaS scaffold), G-11 (offline quality lab), and G-10 custody reconciliation are only advanced within their roadmap owner increment or a documented scope decision.
